# تسک‌های اجرایی پروژه (Task Backlog & Roadmap)

این سند شامل تمامی تسک‌های مهندسی تفکیک‌شده برای هدایت پروژه در برد گیت‌هاب (GitHub Projects / Kanban) است.

---

## اپیک ۱: زیرساخت کلاینت فلاتر دسکتاپ و ضبط صدا (Flutter Desktop & WASAPI)

### تسک ۱.۱: راه‌اندازی پروژه Flutter Desktop برای ویندوز
* **اولویت:** P0 (بسیار بالا)
* **نوع:** Feature / Setup
* **شرح:** ایجاد ساختار پروژه فلاتر در مسیر `apps/client_flutter/` با پیکربندی پشتیبانی ویندوز و سیستم مدیریت وضعیت (Riverpod).
* **معیار پذیرش (Definition of Done):**
  - پروژه روی ویندوز با دستور `flutter run -d windows` بدون خطا بیلد و اجرا شود.
  - ساختار پوشه‌بندی تمیز (Theme, Features, Core) پیاده‌سازی شده باشد.

### تسک ۱.۲: پیاده‌سازی پلاگین بومی C++ برای ضبط صدای سیستم (WASAPI Loopback)
* **اولویت:** P0
* **نوع:** Native Engineering
* **شرح:** توسعه پلاگین C++ در زیرشاخه `windows/` برای اتصال به `IAudioClient` با فلگ `AUDCLNT_STREAMFLAGS_LOOPBACK` و تبدیل صدای سیستم به Linear PCM 16kHz Mono 16-bit.
* **معیار پذیرش:**
  - صدای خروجی اسپیکر/هدفون در حال پخش ویندوز به صورت بافرهای صوتی ۱۶ بیتی دریافت شود.
  - داده‌های صوتی از طریق Dart FFI یا EventChannel بدون Memory Leak به کلاینت فلاتر پاس داده شوند.

### تسک ۱.۳: طراحی رابط کاربری تاریک مدرن و کنترل نشست
* **اولویت:** P1
* **نوع:** UI/UX
* **شرح:** پیاده‌سازی فرم انتخاب زبان، دکمه شروع/توقف نشست، اسلایدر ولوم میکس صدا و نشانگر اتصال.
* **معیار پذیرش:**
  - تم مدرن تیره پیاده‌سازی شود.
  - کاربر بتواند نشست را آغاز، متوقف و مجدداً راه‌اندازی کند.

### تسک ۱.۴: ساخت پنل شناور زیرنویس (HUD Overlay)
* **اولویت:** P1
* **نوع:** UI
* **شرح:** طراحی پنجره سبک و همیشه-رو (Always-on-top) با پس‌زمینه نیمه‌شفاف برای نمایش زنده زیرنویس فارسی.
* **معیار پذیرش:**
  - پنجره بدون حاشیه (Borderless) بالای سایر برنامه‌ها قرار گیرد و با کشیدن موس جابجا شود.

## اپیک ۲: سرور هماهنگ‌کننده و ارتباطات بلادرنگ (Backend Orchestrator)

### تسک ۲.۱: راه‌اندازی سرور هماهنگ‌کننده با Node.js و TypeScript
* **اولویت:** P0
* **نوع:** Backend
* **شرح:** ایجاد سرویس ماژولار در `services/orchestrator/` با Fastify یا Express + WebSocket/Socket.io.
* **معیار پذیرش:**
  - هندلینگ رویداد `session.init` و ایجاد نشست موقت در حافظه/ردیس.
  - اتصال پایدار دوطرفه با کلاینت فلاتر از طریق WSS.

### تسک ۲.۲: پیاده‌سازی ماژول VAD (تشخیص فعالیت صوتی) و چانک‌بندی
* **اولویت:** P0
* **نوع:** Backend / Audio Processing
* **شرح:** ادغام کتابخانه Silero VAD برای تشخیص سکوت و تفکیک جریان پیوسته صوت به قطعات معنادار جمله (بین ۲۰۰ تا ۱۵۰۰ میلی‌ثانیه).
* **معیار پذیرش:**
  - بخش‌های سکوت دور ریخته شوند و فقط گفتار فعال به لایه STT فرستاده شود.
  - در انتهای هر جمله یا پس از گذشت سقف زمانی، رویداد پایان چانک صادر شود.

### تسک ۲.۳: لایه انتزاعی ارائه‌دهندگان هوش مصنوعی (Provider Interfaces)
* **اولویت:** P0
* **نوع:** Architecture
* **شرح:** تعریف تایپ‌ها و اینترفیس‌های مشترک برای `STTProvider`, `TranslationProvider`, `TTSProvider` و ساخت یک `MockProvider` جهت تست‌های آفلاین بدون هزینه.
* **معیار پذیرش:**
  - امکان تعویض ارائه‌دهنده با تغییر متغیر محیطی بدون دستکاری در منطق سرویس.

## اپیک ۳: پایپ‌لاین هوش مصنوعی و دوبله زنده (AI Speech & Dubbing)

### تسک ۳.۱: اتصال سرویس تبدیل گفتار به متن (Streaming STT)
* **اولویت:** P0
* **نوع:** AI Integration
* **شرح:** ارسال چانک‌های صوتی به ارائه‌دهنده STT و دریافت متن همراه با زمان‌مهر واژه‌ها.
* **معیار پذیرش:**
  - تاخیر تشخیص گفتار زیر ۸۰۰ میلی‌ثانیه باشد.

### تسک ۳.۲: ترجمه استریمی به زبان فارسی با کنترل طول کلام
* **اولویت:** P0
* **نوع:** AI Integration / Prompt Engineering
* **شرح:** اتصال به مدل زبانی جهت ترجمه جمله به زبان فارسی با پرامپت هماهنگ‌سازی تعداد هجاها و ریتم گوینده اصلی.
* **معیار پذیرش:**
  - خروجی فارسی روان و بدون تاخیر اضافه استریم شود.

### تسک ۳.۳: ماژول شبیه‌سازی صدا و تبدیل متن به گفتار (Voice Cloning TTS)
* **اولویت:** P1
* **نوع:** AI Integration
* **شرح:** استخراج امبدینگ صدای گوینده در ۵ ثانیه اول و استفاده از مدل Zero-shot TTS برای تولید صدای فارسی با مشخصات صوتی گوینده اصلی.
* **معیار پذیرش:**
  - صدای خروجی شباهت کیفی با جنس صدای گوینده اصلی داشته باشد.
  - در صورت خطا یا تاخیر بالا، به صدای فارسی پیش‌فرض Fallback کند.

### تسک ۳.۴: پیاده‌سازی الگوریتم تنظیم سرعت تطبیقی (Time-Stretching)
* **اولویت:** P1
* **نوع:** Audio DSP
* **شرح:** تنظیم سرعت استریم صوتی فارسی (بین ۰.۸۵x تا ۱.۲x) با حفظ زیروبمی صدا (Pitch Preservation) برای تطابق با بازه زمانی گوینده اصلی.
* **معیار پذیرش:**
  - صدا دچار اکو، رباتیک‌شدن یا ناهماهنگی زمانی نگردد.

## اپیک ۴: هماهنگ‌سازی لب (Lip-Sync Engine - فاز تکمیلی)

### تسک ۴.۱: راه‌اندازی GPU Worker با Python و PyTorch
* **اولویت:** P2
* **نوع:** Machine Learning / Worker
* **شرح:** ایجاد سرویس پایتونی مجهز به PyTorch برای اجرای مدل‌های هماهنگ‌سازی لب (نظیر MuseTalk یا LatentSync).
* **معیار پذیرش:**
  - دریافت فریم چهره + چانک صوتی و تولید فریم دهان در کمتر از ۵۰ میلی‌ثانیه به ازای هر فریم روی کارت گرافیک مناسب.

### تسک ۴.۲: ترکیب نرم چهره و تصویر اصلی (Seamless Face Blending)
* **اولویت:** P2
* **نوع:** Computer Vision
* **شرح:** ماسک‌گذاری لبه‌های ناحیه لب و دهان و ادغام بدون مرز با ویدیوی اصلی ویندوز.
* **معیار پذیرش:**
  - هیچ مرز یا پرش تصویری (Jittering) در فریم‌های نهایی مشاهده نشود.

### تسک ۴.۳: مکانیزم سوییچ خودکار به حالت صوتی (Latency Circuit Breaker)
* **اولویت:** P1
* **نوع:** Reliability
* **شرح:** اگر تاخیر صف کارت گرافیک از ۱۵۰۰ میلی‌ثانیه گذشت، سیستم به صورت خودکار Lip-sync را موقتاً قطع کرده و فقط صدا و زیرنویس پخش کند.
* **معیار پذیرش:**
  - پخش صدای ترجمه‌شده حتی در صورت گلوگاه پردازش تصویر بدون قطعی ادامه یابد.
